MUST HAVE CHECKLIST
====================================================

[1] BluestIo implementing all 7 BleIo trait methods
    STATUS: PASS
    EVIDENCE: src/transport/ble/bluest.rs implements listen, connect,
    start_advertising, stop_advertising, start_scanning, local_addr,
    adapter_name — all 7 methods of the BleIo trait.

[2] Central role: start_scanning, connect produce working BLE connections
    STATUS: PASS
    EVIDENCE: bluest.rs start_scanning() creates BluestScanner wrapping
    bluest Adapter::discover_devices(). connect() calls
    Device::open_l2cap_channel(psm, secure=false) producing BluestStream.
    Both use real bluest API calls with proper error handling.

[3] Peripheral role: listen, start_advertising, stop_advertising return
    TransportError with clear message
    STATUS: PASS
    EVIDENCE: All three methods return
    Err(TransportError::NotSupported("... central-only ...".into()))
    with descriptive messages.

[4] BleAddr support for UUID-based device identification
    STATUS: PASS
    EVIDENCE: src/transport/ble/addr.rs defines
    BleDeviceAddr::Uuid([u8; 16]) variant. BleAddr::from_bluest_id()
    and BleAddr::to_bluest_id() handle conversion. Display/parse
    support UUID format.

[5] All cfg gates widened to include macOS
    STATUS: PARTIAL FAIL
    EVIDENCE:
    - transport/mod.rs: PASS — 21 instances of
      cfg(any(target_os = "linux", target_os = "macos"))
    - node/mod.rs create_transports: PASS — cfg(all(feature = "ble-macos",
      not(test))) block creates BluestIo on macOS
    - io.rs: PASS — cfg(feature = "ble-macos") mod bluest + re-export
    - ble/mod.rs: PASS — DefaultBleTransport = BluestIo on macOS
    - Cargo.toml: PASS — bluest gated to cfg(target_os = "macos")
    - node/lifecycle.rs: FAIL — BLE address resolution in
      initiate_peer_connection (line 123) is still
      #[cfg(target_os = "linux")] only. macOS falls to the
      #[cfg(not(target_os = "linux"))] branch which logs
      "BLE transport not available on this platform" and skips.
    - node/mod.rs resolve_ble_addr: FAIL — function at line 883 is
      gated with #[cfg(target_os = "linux")] only, not widened.
    IMPACT: macOS nodes cannot initiate BLE connections to statically
    configured BLE peers. Scan-based auto-connect (via BleTransport)
    still works, but explicit peer addresses with transport="ble"
    in config will be silently skipped on macOS.

[6] DefaultBleTransport resolves to BluestIo on macOS (non-test builds)
    STATUS: PASS
    EVIDENCE: ble/mod.rs line 60-61:
    #[cfg(all(feature = "ble-macos", not(test)))]
    pub type DefaultBleTransport = BleTransport<io::BluestIo>;

[7] bluest pinned to specific version in Cargo.toml
    STATUS: PASS (minor version discrepancy)
    EVIDENCE: Cargo.toml has bluest = { version = "0.6.9", ... }
    Plan specified v0.6.10. However, 0.6.9 is a valid pin and the
    crate compiles and works. This is acceptable — the plan's version
    was a recommendation, not a strict requirement, and pinning to
    a specific version satisfies the intent.

[8] Error mapping from bluest errors to TransportError
    STATUS: PASS
    EVIDENCE: bluest.rs maps errors to:
    - TransportError::Io (general bluest errors via io::Error::other)
    - TransportError::LinkFailed (connection failures)
    - TransportError::SendFailed / RecvFailed (stream I/O)
    - TransportError::InvalidAddress (bad address format)
    All use existing TransportError variants with context strings.

MUST HAVE SUMMARY: 7/8 PASS, 1 PARTIAL FAIL (cfg gates not fully widened)
