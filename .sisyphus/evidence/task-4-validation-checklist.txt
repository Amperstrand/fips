PHASE 1: Isolated Directional iperf (TEST E)
---------------------------------------------
Purpose: Verify each direction works independently before testing both

Step 1.1: Linux → macOS (macOS as peripheral, receives data)
  Command: bash testing/ble/run-ble-test-campaign.sh --test E

    - /tmp/fips-ble-campaign/testE-linux-to-mac-iperf     — iperf summary

    - /tmp/fips-ble-campaign/testE-linux-peer-log           — Linux FIPS log
  Pass criteria:
    - iperf summary shows non-zero end throughput
    - No stall/reset in either log

Step 1.2: macOS → Linux (macOS as central, sends data)
  Command: (same run, opposite direction)
  Artifacts to inspect:
    - /tmp/fips-ble-campaign/testE-mac-to-linux-iperf      — iperf summary
    - Same peer logs as Step 1.1
  Pass criteria:
    - iperf summary shows non-zero end throughput
    - No stall/reset in either log

PHASE 2: Ping Under Load
-------------------------
Purpose: Verify latency remains acceptable during bulk transfer

Step 2.1: Start iperf in one direction, then run ping
  Steps:
    1. Start FIPS on both sides with updated writer
    2. Start iperf (one direction)
    3. Concurrently: ping6 <peer-fips-address> (10 pings, 1s interval)
  Artifacts:
    - iperf output
    - ping output (latency values)
  Pass criteria:
    - All pings return (no 100% loss)
    - Median latency < 500ms
    - Max latency < 1000ms
