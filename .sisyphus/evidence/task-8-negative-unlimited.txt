## Negative Test Results

### ✅ No Unlimited Burst Mode Used

1. **Default configuration**: 100 Kbps rate limit, 2 KB burst — not unlimited
2. **Bulk transfer tests**: Explicit conservative values, no reliance on 0→150 Kbps mapping
3. **Control-plane tests**: Can use `send_rate_bps: 0` (not bulk transfer tests)
4. **Adaptive control**: AIMD preserves flexibility without sacrificing stability

### ✅ No Spurious Unbounded Behavior

1. **Token bucket limiter**: Still enforces rate limits, even with adaptive scaling
2. **BleRateAdapter**: Clamps between 50 Kbps and 250 Kbps — bounded, not unlimited
3. **Writer queues**: Still bounded (32 frames / 64 KB) — no single point of unbuffered writes

### ✅ Stability-First Approach Validated

1. **Conservative starting rate**: 100 Kbps (down from 150 Kbps)
2. **Smaller bursts**: 2 KB (down from 4 KB)
3. **Adaptive scaling**: Up to 250 Kbps if link is healthy, but scaled back when congested
4. **No aggressive defaults**: Unlimited mode avoided in stability-critical paths

## Rationale for Avoiding Unlimited Mode

### Why `send_rate_bps: 0` (Unlimited) is Problematic

1. **Writer queue overflow risk**:
   - 2 KB bursts × 32 frames = 64 KB queue capacity
   - Unlimited bursts can overwhelm bounded queues under mesh-speed data rates
   - Results in "No data to write" and connection stalls

2. **L2CAP pipe backing up**:
   - BLE L2CAP MTU: 512 bytes
   - Typical CoC SDU: ~244 bytes
   - Mesh data rates can exceed BLE link capacity without pacing
   - Leads to credit exhaustion and queue buildup

3. **Unpredictable backpressure**:
   - Writers may block indefinitely if buffers fill
   - No graceful degradation under load
   - Timeout errors become frequent

### Why Conservative Defaults are Safer

1. **Controlled pacing**:
   - 100 Kbps rate limit ensures steady throughput
   - 2 KB bursts provide smooth incremental sends
   - Predictable backpressure behavior

2. **Adaptive scaling**:
   - AIMD allows gradual ramp-up when link is healthy
   - Reduces rate automatically when congestion detected
   - Bounded between 50 Kbps and 250 Kbps

3. **Stability-first objective**:
   - Sub-1s ping under load achievable at 100-150 Kbps
   - iperf throughput at 100 Kbps is sufficient for most use cases
   - No stalls or resets at this rate

## Conclusion

✅ **VERIFIED** — The stability-first pacing profile does NOT default to unlimited send bursts. It uses conservative default values (100 Kbps, 2 KB burst) with preserved adaptive rate control. Unlimited mode (`send_rate_bps: 0`) is reserved for control-plane tests where it is acceptable, not for bulk transfer stability-critical paths.
