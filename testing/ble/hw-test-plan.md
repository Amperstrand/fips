# BLE Hardware Test Plan — Capability Signaling

Tests the BLE peer capability signaling feature (commit `8c388cf` and
subsequent). Verifies backwards-compatible capability exchange during
pubkey exchange and correct tie-breaker behavior for all role
combinations.

## Test Matrix

### Mac↔Mac directionality verification

| # | Name | Mac A | Mac B | Expected Outcome |
|---|------|-------|-------|------------------|
| M1 | Mac A outbound / Mac B inbound | `scan=true, advertise=true, accept_connections=true` | `scan=true, advertise=true, accept_connections=true` | Exactly one BLE link forms; smaller `NodeAddr` wins outbound via tie-breaker |
| M2 | Mac B outbound / Mac A inbound | Same configs, but use keys/configs such that B has smaller `NodeAddr` | Same | Exactly one BLE link forms; B wins outbound, A keeps inbound |
| M3 | Both peers scanning+advertising | Both full dual-role | Both full dual-role | Race resolves deterministically; no duplicate active links |
| M4 | Reconnect after disconnect | Bring link up, then stop one side and restart it | Other side remains up | Link re-establishes after rediscovery/probe |
| M5 | Large payload / frame coalescing | Send burst traffic over established link | Receive burst traffic | No framing corruption; FMP traffic survives CoreBluetooth stream coalescing |

### Existing Linux↔macOS capability signaling cases

| # | Name | Mac Capabilities | Linux Capabilities | Expected Outcome |
|---|------|-----------------|-------------------|------------------|
| 1 | normal | `macos_default()` (PREFER_OUTBOUND) | `linux_default()` (full, no pref) | Mac outbound wins via preference tier |
| 2 | linux-central-only | `macos_default()` | `central_only()` (accept_connections=false) | Mac outbound wins; Linux accept_loop keeps inbound from Mac |
| 3 | legacy | Sends 33-byte (no flags) | `linux_default()` | Old wire format works; Linux assumes full capability; NodeAddr decides |
| 4 | speedtest | `macos_default()` | `linux_default()` | Functional throughput test with iperf3 via TUN |
| 5 | isolated-direction speedtest | `macos_default()` | `linux_default()` | Run `linux -> mac` and `mac -> linux` on separate fresh peer sessions to remove test-order ambiguity |

## Prerequisites

- Mac with Bluetooth (this machine) running macOS build with `--features ble-macos`
- Linux machine with BLE adapter in radio range (~10m)
- Both machines on same network for SSH access
- `iperf3` installed on both for throughput tests
- Root/sudo on both machines (for TUN interface)

## Test Execution

### Step 1: Build and Deploy

**Mac** (run from this repo):
```bash
CARGO_TARGET_DIR=/tmp/fips-target cargo build --release --features ble-macos
```

**Linux** (SSH into the machine):
```bash
cd /path/to/fips
git fetch origin
git checkout macos-ble
git pull
cargo build --release --features ble
sudo systemctl stop fips
sudo cp target/release/fips /usr/local/bin/fips
```

### Step 2: Run Each Test

For each test in the matrix:

1. Deploy the appropriate config to both Mac and Linux
2. Start FIPS on both (Linux: `systemctl start fips`, Mac: `sudo ./fips -c config.yaml`)
3. Wait for BLE discovery and connection (~10-30s)
4. Verify connection established:
   - `fipsctl show links` — should show BLE link
   - `fipsctl show peers` — should show authenticated peer
5. Capture debug log with ephemeral keys for offline decoding
6. Run connectivity test: `ping6 <peer_npub>.fips`
7. Run throughput test: `iperf3 -c <peer_fd00_addr>` (through TUN)
8. Stop and collect logs

### macOS unattended test setup

Before running the BLE campaign unattended on the Mac, install the narrow test
helper once:

```bash
cp testing/ble/install-macos-test-helper.sh /tmp/install-macos-test-helper.sh
sudo bash /tmp/install-macos-test-helper.sh
```

This installs `/usr/local/libexec/fips-test/macos-test-helper.sh` and a scoped
sudoers entry so the campaign runner can start/stop the macOS `fips` process
without broad passwordless sudo.

### Mac↔Mac specific execution notes

Use two physical Macs in radio range. On each machine:

```bash
CARGO_TARGET_DIR=/tmp/fips-target cargo build --release --features ble-macos
sudo bash /tmp/fips-mac.sh
```

For M1/M2, use different identity seeds or persistent identities so the two
nodes have stable, distinct `NodeAddr` values. Record each node's `NodeAddr`
before testing; the smaller one should win the outbound tie-break.

For Linux↔macOS test evidence, also preserve the per-test provenance files
generated by `testing/ble/run-ble-test-campaign.sh`:

- `testA-provenance.txt`
- `testB-provenance.txt`
- `testC-provenance.txt`
- `testD-provenance.txt`
- `testE-provenance-linux-to-mac`
- `testE-provenance-mac-to-linux`

Each file records local and remote branch, commit, binary version string, git
dirty state, and UTC timestamp. This is required because the current Linux test
node may be on the same branch but a different commit or a dirty working tree.

`TEST E` is the directional performance isolation check. It restarts both nodes
between phases so `linux -> mac` and `mac -> linux` each run on a fresh BLE
peer/session instead of inheriting any failure caused by the opposite direction.

Success criteria for Mac↔Mac:

1. Each run results in exactly one authenticated BLE peer on both sides.
2. The initiating side matches the expected `NodeAddr` tie-break winner.
3. `fipsctl show peers` reports `transport_type: ble` and `connectivity: connected`.
4. Tree announce / filter announce / MMP traffic flows in both directions.
5. Large payload bursts do not produce framing, version, or AEAD errors.

### Step 3: Decode Captured Traffic

Use the debug ephemeral key log (`debug_ephemeral_key_log_path`) to
decrypt captured BLE L2CAP traffic. Verify:
- Pubkey exchange frame: 34 bytes (`[0x00][pubkey:32][flags:1]`)
- Capability flags byte matches expected value
- Noise IK handshake succeeds
- FMP data flows bidirectionally
